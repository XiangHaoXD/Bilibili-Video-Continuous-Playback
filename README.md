# URL Logger - Chrome Extension

一个轻量的 Chrome 浏览器扩展，用于自动记录访问的 URL、检测网页媒体播放状态，并在视频播放完毕后自动切换标签页。

## ✨ 主要功能

### 📝 URL 记录
- 自动记录当前活动标签页的 URL 和时间戳
- 按日期分块存储（每天每 100 条一块），只保留最近 **3 天**
- 支持一键下载当日记录为 txt 文件（文件名 `urls-YYYY-MM-DD.txt`）
- 切日按**本地时区**计算，凌晨的记录不会落到前一天

### 🎬 媒体检测
- 实时检测页面主文档中的视频和音频播放状态
- 区分“正在播放”“已暂停”和“已播放完成”三种状态
- 记录媒体数量（视频/音频）
- 使用 `play` / `pause` / `ended` 事件驱动，无定时轮询

### 📺 直播识别
- 通过 `duration === Infinity`、`duration === 0` 且已播放、DVR `seekable` 特征识别直播
- 元数据尚未加载（`duration` 为 `NaN`）时**不会**误判为直播
- 页面只要存在直播视频，整页按直播处理：只记录 `[LIVE]`，**绝不自动切换**

### 🔄 自动切换标签页
- 视频播放完毕后自动切换到下一个标签页
- 可自由开启/关闭，与“开始/停止记录”相互独立
- 只激活目标标签页，**不会把浏览器窗口弹到前台**；全屏游戏或窗口在后台时不会被抢焦点
- 在**最后聚焦窗口**的 `http(s)` 标签页之间循环，跳过 `chrome://`、扩展页、新标签页
- **不检查目标页状态**：直接切到标签栏里的下一个 `http(s)` 标签页，不管它是直播、暂停还是已播完
- 每次播完只切换一次，不会连环切换多个标签页
- 1.5 秒延迟 + 切换前二次确认（重新查询当前页媒体状态）
- 防重复触发：同一标签页因播完只切换一次，手动切回不会被再次切走；重新播放后才会重新生效
- 该去重状态会保存到 `storage.session`，Service Worker 被回收后依然有效

### 👍 自动点赞（B站，可选）
- 视频播放结束后，优先点击页面自己的点赞按钮，按钮会像手动点赞一样点亮
- **后台标签页里播放结束的视频也会点赞**，不要求标签页处于当前活动状态
- 只认**主播放器视频**结束，广告/预览视频结束不会提前点赞
- 点击前先查近期是否已赞，已赞直接跳过；找不到按钮或点击未生效时回退到 B 站官方 `archive/like` 接口
- 只在 `bilibili.com/video/...` 页面生效，需要当前浏览器已登录 B 站
- 同一稿件只点一次；已点亮时跳过，不会把赞点掉
- 与“开始/停止记录”“自动切换标签页”都相互独立
- 独立开关，默认关闭

## 📦 安装方法

### 开发者模式安装

1. 下载或克隆此项目到本地

2. 打开 Chrome 浏览器，进入扩展程序管理页面
   - 访问 `chrome://extensions/`
   - 或点击右上角菜单 → 更多工具 → 扩展程序

3. 启用“开发者模式”（右上角开关）

4. 点击“加载已解压的扩展程序”

5. 选择 `Urllog` 文件夹（不是仓库根目录）

6. 扩展安装完成！

## 🚀 使用指南

### 基本操作

1. **开始记录**
   - 点击扩展图标打开弹窗
   - 点击“开始记录”按钮
   - 状态显示为“正在记录中...”，按钮变绿

2. **停止记录**
   - 点击“停止记录”按钮
   - 状态显示为“记录已停止”，此后媒体事件不再写日志
   - 已开启的“自动切换标签页”仍然独立生效

3. **下载记录**
   - 点击“下载今日日志”按钮
   - 文件自动保存为 `urls-YYYY-MM-DD.txt`（覆盖同名文件，不弹保存框）

4. **清空记录**
   - 点击“清空今日日志”，确认后删除当天全部记录

5. **自动切换标签页**
   - 打开弹窗，启用“自动切换标签页”开关
   - 当视频播放完毕后，1.5 秒后自动切换到下一个网页标签页
   - 切换在后台完成，只激活标签页，不会把浏览器窗口弹到最前
   - 不检查目标页是直播、暂停还是已播完，只切换一次
   - 记得在 B 站播放设置中开启“自动开播”，否则切换过去后视频可能不会自动开始

6. **自动点赞（B站）**
   - 打开弹窗，启用“自动点赞（B站视频）”开关
   - 在 B 站视频播放结束后，优先点击页面上的点赞按钮，按钮会像手动点赞一样点亮
   - 后台标签页里播放结束的视频也会点赞
   - 如果页面结构变化导致找不到按钮，会自动回退到官方接口；这种情况按钮可能不会立即变色，刷新后可见
   - 需要浏览器已登录 B 站；未登录时会跳过并在页面控制台提示

### 日志格式示例

```
14:30:25 https://www.bilibili.com/video/BV1xx411c7mD [PLAYING: 1V 0A]
14:32:40 https://www.bilibili.com/video/BV1xx411c7mD [PAUSED: 1V 0A]
14:35:10 https://www.bilibili.com/video/BV1xx411c7mD [PLAYED: 1V 0A]
14:40:03 https://live.bilibili.com/12345 [LIVE]
```

格式说明：
- 时间戳（本地时区，时:分:秒，24 小时制）
- URL 地址
- 媒体状态标记：
  - `[PLAYING: XV YA]` - 正在播放 X 个视频，Y 个音频
  - `[PAUSED: XV YA]` - 已暂停（播放进度大于 0）X 个视频，Y 个音频
  - `[PLAYED: XV YA]` - 已播放完成 X 个视频，Y 个音频
  - `[LIVE]` - 直播页面

同一个 URL 在“开始播放”“暂停”“播放结束”时各会记录一条，因此日志中可能出现多行相同 URL。

## 🔧 技术特性

### Manifest V3
- 采用 Manifest V3，使用 Service Worker 替代 Background Page
- 最低支持 Chrome 116（依赖 `chrome.offscreen.hasDocument` 与 `chrome.storage.session`）
- 无远程代码、无 `eval`

### 媒体检测
- **主文档扫描**：只扫描顶层文档中的 `<video>` / `<audio>`
- **事件驱动**：捕获 `play` / `pause` / `ended`，不做定时轮询
- **暂停判定**：`paused` 且播放进度大于 0，记录 `[PAUSED]`，避免出现无标记的裸 URL
- **直播判定**：`duration` 为 `Infinity`；`duration` 为 `0`、正在播放且已有进度；或 `seekable` 起点 > 300 秒且贴近末尾
- **页面级直播标记**：任一视频被判为直播，整页标记为直播，不再统计普通媒体
- **健壮性**：扩展上下文失效时自动移除监听器

### 数据存储
- 使用 `chrome.storage.local` 本地存储
- 按天分块：`logs-YYYY-MM-DD-c0`、`-c1`……每块最多 100 条，追加时只重写最后一块
- 兼容旧版单 key 数组 `logs-YYYY-MM-DD`，首次访问时自动拆分迁移
- 标签页状态按 `tabState:<tabId>` 单独存放于 `chrome.storage.session`，媒体事件只写自己那一份，不再重写整个 map
- 已切换标签页列表保存在 `storage.session`，Service Worker 被回收后仍能避免重复切换
- 每天首次运行（含跨日）时自动清理 3 天前的日志

### 自动切换机制
- `switchedTabs` 记录已触发过切换的标签页，避免重复切换（持久化到 `storage.session`）
- `tabSwitchTimers` 管理待执行定时器，手动切回标签页时取消
- 切换前重新查询媒体状态，直播、重新播放、已无结束视频都会放弃切换
- 按标签栏顺序直接选择下一个 `http(s)` 标签页，不检查目标页是直播、暂停还是已播完
- 每次播完只调用一次 `tabs.update`；刚切过去的页面 3 秒内自带的 ended 状态不会触发连锁切换
- 目标标签页只从 `http(s)` 页面中选择，固定使用最后聚焦窗口
- 只调用 `tabs.update` 激活标签页，不调用 `windows.update`，因此后台/最小化窗口不会被弹到前台

### 自动点赞机制
- 后台在收到“视频播完”状态且开关开启时，向内容脚本发送 `AUTO_LIKE`；**不要求标签页处于活动状态**，后台标签页里播完也会点赞
- 只认主播放器视频结束（`#bilibili-player` / `.bpx-player-container` 等容器，识别不到时取时长最长的视频）
- 内容脚本先找页面上的点赞按钮（`.video-like`、旧版 `.like`，并递归 open shadow root，最多扫描 5000 个节点）
- 点击前先查 `has/like`，近期已赞过的视频直接跳过，降低误取消赞的风险
- 按钮未点亮时直接 `click()`，由 B 站自己完成点赞请求和按钮点亮，和手动点赞一致
- 按钮已点亮（`on` / `liked` / `aria-pressed` / 标题带“取消点赞”）时跳过，避免误取消赞
- 找不到按钮或点击后 1 秒内未点亮时，回退到官方接口 `archive/like`
- 内容脚本从 URL 取 `bvid` / `av` 号，从 `bili_jct` Cookie 取 CSRF Token；BV 号按原大小写比对，只有 av 前缀做归一化
- `code === 0` 视为成功，`65006`（重复点赞）按成功跳过；其他错误只写控制台，不弹窗打扰
- 同一页面内按稿件去重，重复 `ended` 不会重复请求；失败后允许下次再试
- 不新增任何扩展权限：按钮点击和接口请求都在 B 站页面上下文完成

## ⚙️ 权限说明

| 权限 | 用途 |
|------|------|
| `tabs` | 读取标签页 URL/顺序，实现日志与自动切换 |
| `downloads` | 下载日志 txt 文件 |
| `storage` | 存储访问记录、设置与去重状态 |
| `offscreen` | 创建离屏文档，用 Blob 生成 txt |
| `webNavigation` | 识别 SPA 的 `pushState` / `replaceState` / hash 路由变化 |
| `<all_urls>` | 在所有网页的主 frame 注入内容脚本以检测媒体 |

## ⚠️ 注意事项与已知限制

1. **隐私保护**
   - 所有浏览记录只存储在本地浏览器中，不会上传到任何服务器
   - 唯一的外发请求是自动点赞：开启后会把当前视频的 `bvid` / `aid` 和 CSRF Token 发送给 B 站官方点赞接口
   - 日志 URL 会对 `token` / `access_token` / `uid` / `SESSDATA` / `bili_jct` 等敏感查询参数，以及 32 位以上的长 token 值脱敏为 `***`；脱敏在写入时完成，历史已写入的记录不会自动改写
   - 可随时清除存储数据

2. **性能影响**
   - 事件驱动检测，无定时轮询
   - 日志分块追加，避免每次重写全天数据
   - 点赞按钮查找最多扫描 5000 个节点，避免大页面卡顿
   - 对浏览器性能影响很小

3. **兼容性**
   - 仅支持基于 Chromium 的浏览器（Chrome、Edge、Brave 等），版本 116+
   - 内容脚本只注入主 frame：**不检测 Shadow DOM 与 iframe 内的媒体**
   - 依赖 `<video>` / `<audio>` 元素，Canvas/WebGL 自绘播放器无法检测

4. **自动切换功能**
   - 仅在**视频**播放完毕时触发，音频结束不切换
   - 延迟 1.5 秒后切换，切换前会二次确认
   - 只在同一窗口的 `http(s)` 标签页之间循环，**不检查目标页状态**，只切换一次
   - 只切换标签页，**不会把浏览器窗口拉到前台**；窗口在后台或全屏游戏时不会被抢焦点，需要切回浏览器才能看到新页面
   - 同一标签页播完只切换一次，手动切回后可以停留；重新播放后再次生效
   - 在后台标签页（非当前选中页）里播完的视频不会触发切换；之后手动切回该页时也不会被自动切走，只会补记一条 `[PLAYED]` 日志
   - 切换只负责激活标签页，不保证新页面自动开始播放（B 站需开启“自动开播”）

5. **自动点赞功能**
   - 仅在 `bilibili.com/video/...` 页面、**主视频播放结束**时触发；直播、音频结束、番剧页、广告/预览视频结束不处理
   - **后台标签页里播放结束的视频也会点赞**，不要求标签页处于当前活动状态
   - 需要浏览器已登录 B 站；未登录、Cookie 失效或触发风控时会跳过，只在页面控制台输出原因
   - 优先点击页面自己的点赞按钮，正常情况下按钮会像手动点赞一样点亮；如果 B 站改版导致找不到按钮，会回退到官方接口，这时按钮可能不会立即变色（刷新后可见）
   - 同一稿件只点一次；按钮已点亮或近期已赞时直接跳过，不会把赞点掉
   - 关闭开关后不会再发起任何点赞请求

6. **记录范围**
   - 日志只记录**当前活动标签页**，后台标签页的加载与播放不记录（自动点赞不受此限制）
   - SPA 路由变化（`pushState` / `replaceState` / hash）会通过 `webNavigation` 记录（仍限当前活动标签页）
   - 只有“今天”的日志可以下载，历史日志（最多 3 天）没有浏览/导出界面

## 💡 常见问题

### Q: 为什么有些视频没有被检测到？
A: 可能原因：
- 视频位于 iframe 或 Shadow DOM 内（当前轻量版只检测主文档）
- 播放器用 Canvas/WebGL 自绘，没有 `<video>` 元素
- 页面是 `chrome://`、扩展页等无法注入内容脚本的受限页面
- 视频元数据尚未加载（此时 `duration` 为 `NaN`，不会计入播放状态）

### Q: 自动切换功能不工作？
A: 请检查：
- 是否已启用“自动切换标签页”开关
- 当前标签页中的视频是否确实播放完毕（音频结束不会触发）
- 浏览器是否有多个 `http(s)` 标签页
- B 站是否开启了“自动开播”，否则切换过去后不会自动播放
- 是否停留在直播页（直播页只记录，不切换）
- 目标页状态现在不参与判断：切过去可能是直播、暂停或已播完的页面

### Q: 自动点赞没有生效？
A: 请检查：
- 是否已启用“自动点赞（B站视频）”开关
- 当前页面是否是 `bilibili.com/video/...`，且**主视频**确实播放结束（直播、番剧页、广告/预览视频结束不触发）
- 浏览器是否已登录 B 站（需要有 `bili_jct` Cookie）
- 打开网页 F12 → Console，看是否有 `[URL Logger] 自动点赞跳过：...` 提示
- 扩展更新后需要刷新 B 站页面，旧页面上运行的还是旧版内容脚本
- 正常路径会直接点击页面按钮并点亮；如果 B 站改版导致找不到按钮，会回退到接口，这种情况需要刷新页面才能看到点赞状态
- 后台标签页里播完的视频也会点赞，不需要把页面切到前台

### Q: 为什么停止记录后还有日志？
A: v2.4.0 起，停止记录后媒体事件不再写日志。“自动切换标签页”和“自动点赞（B站视频）”都是独立开关，仍会在视频结束时生效。如需全部停止，请同时关闭记录与两个自动开关。

### Q: 如何导出历史记录？
A: 目前只能下载当天记录。历史数据（最近 3 天）可以用
`chrome.storage.local.get(null, console.log)` 查看，key 形如 `logs-YYYY-MM-DD-c0`。
如需长期归档，可以每天下载一次 txt。

### Q: 扩展占用多少存储空间？
A: 取决于使用频率。平均每天约 10-50 KB，只保留 3 天，远低于 `chrome.storage.local` 的 10 MB 配额。
